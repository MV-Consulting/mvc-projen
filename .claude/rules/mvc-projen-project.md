# Project: mvc-projen

**Last Updated:** 2026-07-21

## Overview

`mvc-projen` (`@mavogel/mvc-projen` on npm) is [MV Consulting](https://manuel-vogel.de/)'s baseline [projen](https://projen.io/) module: a scaffolder that provides opinionated defaults for AWS CDK construct libraries. Built with JSII so the same source compiles to TypeScript/JavaScript (npm), Python (PyPI), and Go (GitHub module).

## Technology Stack

- **Language:** TypeScript, compiled via JSII (`jsiiVersion: ~5.9.0`)
- **Scaffolding framework:** projen (`projenVersion` in `.projenrc.ts` — see `mvc-projen-toolchain-maintenance.md`)
- **Testing:** Jest + ts-jest
- **Package manager:** npm (not yarn/pnpm)
- **Lint:** ESLint (ignores `**/*-function.ts`, `examples/`)

## Directory Structure

```
src/
  index.ts              # exports all projects
  projects/
    cdk-construct.ts    # MvcCdkConstructLibrary — the main scaffolder class
assets/
  cdk-construct/        # TS templates copied into generated projects (src, tests, integ-tests)
  common/                # shared GitHub templates (issue/PR templates, CONTRIBUTING, prettierrc)
test/
  cdk-construct.test.ts
projenrc/                # projen 0.101+ helper root, own tsconfig
.projenrc.ts             # this repo's OWN projen config (not the scaffolder — see below)
```

**Don't confuse the two projen configs:** `.projenrc.ts` configures *this repository's own* build (a `cdk.JsiiProject`). `src/projects/cdk-construct.ts` defines `MvcCdkConstructLibrary`, the class that scaffolds *other people's* CDK construct projects. Settings in one do not apply to the other — e.g. this repo's own `typescriptVersion` pin (`mvc-projen-toolchain-maintenance.md`) is NOT inherited by generated consumer projects.

## Development Commands

| Task | Command |
|------|---------|
| Full build (synth + compile + test + lint + package) | `npm run build` |
| Test with coverage | `npm test` |
| Test, watch mode | `npm run test:watch` |
| Lint | `npm run eslint` |
| Compile only | `npm run compile` |
| Package all targets (npm/Python/Go) | `npm run package-all` |
| Package one target | `npm run package:js` \| `package:python` \| `package:go` |
| Regenerate project files from `.projenrc.ts` | `npx projen` |
| Remove generated files + deps | `npm run clobber` |
| Release (CI-triggered on main) | `npm run release` |

Scaffold a new project from this module:

```bash
mkdir my-new-construct && cd my-new-construct
npx projen new --from @mavogel/mvc-projen@~0 --cdkVersion=2.261.0 --package-manager=npm
```

## Architecture Notes — Key Design Patterns

1. **Asset-based generation** — templates in `assets/` are copied into generated projects at synthesis time (see `SampleCode` component in `cdk-construct.ts`), not inlined as string literals.
2. **Dynamic configuration** — `baseAssetsDirectory` defaults to `${cwd()}/node_modules/@mavogel/mvc-projen/assets`, overridable via `MvcCdkConstructLibraryOptions`.
3. **Workflow modification** — `cdk-construct.ts` post-processes the generated `build.yml` to splice in an `awslint` step. This ONLY applies to projects generated by `MvcCdkConstructLibrary` — this repo's own `.github/workflows/build.yml` does not run awslint.
4. **Multi-language publishing** — JSII compiles one TypeScript source to npm, PyPI, and a Go module (`publishToGo`/`publishToPypi` in `.projenrc.ts`).

## Generated Project Defaults (MvcCdkConstructLibrary)

Current as of `src/projects/cdk-construct.ts`:

- **Node / Lambda runtime:** 24.x / `NODEJS_24_X` (`awsSdkConnectionReuse: false` — that setting doesn't exist in AWS SDK JS v3)
- **Copyright:** MV Consulting GmbH, 2025 · **License:** Apache-2.0
- **Package manager:** npm · **Auto-approve:** dependabot + bot accounts via `PROJEN_GITHUB_TOKEN` secret
- **Dependabot:** weekly, groups everything except `aws-cdk*` and `projen` (both excluded — `aws-cdk*` is manually managed, `projen` needs the toolchain workflow, see `mvc-projen-toolchain-maintenance.md`)
- **Integration tests:** `eu-west-1` + `eu-west-2` by default, override via `integTestRegions`
- **Extra deps injected:** `cdk-nag@^3.0.1` (requires `aws-cdk-lib >= 2.257.0` — cdk-nag v3 uses CDK's native `Validations`/`IPolicyValidationPlugin` framework instead of `Aspects`, see `cdk-nag`'s `MIGRATION.md`), and version-capped `@aws-cdk/integ-runner` / `@aws-cdk/integ-tests-alpha` / `awslint` pinned to match the consumer's `cdkVersion` (`LAST_INTEG_RUNNER_VERSION` in `cdk-construct.ts` is a manually-verified cap, currently `2.203.0` — re-check `npm view @aws-cdk/integ-runner versions` periodically)

## Testing

- Unit tests in `test/`, Jest + ts-jest, coverage in json/lcov/clover/cobertura/text
- Test patterns: `<rootDir>/@(src|test)/**/*(*.)@(spec|test).ts?(x)` and `__tests__/**` (also matched under `projenrc/`)
- Generated consumer projects get integration tests via `@aws-cdk/integ-runner` (`npm run integ-test`), deployed to `integTestRegions`, snapshots updated with `--update-on-failed`

## JSII Constraints (public API surface)

- All public APIs must be JSII-compatible (no TS-only features)
- Use `readonly` for immutable properties
- Interface names start with a capital letter; enum values use PascalCase

## Important

- **Never hand-edit generated files** (`package.json`, `.github/workflows/*.yml`, `tsconfig*.json`, etc.) — edit `.projenrc.ts` (this repo) or `cdk-construct.ts` (the scaffolder) and run `npx projen`.
- Commit types: `feat, fix, chore, refactor, perf, docs, style, test, build, ci` (conventional commits, enforced by commitlint + PR title lint). Only `feat/fix/chore/refactor/perf` are releasable.
